# ROS 2 实时红色识别：排错记录

按实际排查顺序保留中间现象。正常启动和最终参数见[最终记录](实验日志/ROS2/视觉/ROS2-B-261122-001.md)。

| 现象 | 当次处理或结论 |
| --- | --- |
| Ubuntu 起初没有 `/dev/video*` | Windows 找到 USB 摄像头 `04f2:b758`。`usbipd bind` 要管理员权限；`Shared` 只代表已允许共享，执行 `attach` 后用 `usbipd list` 确认 `Attached`。 |
| 显示 `Attached`，Ubuntu 仍没视频设备 | 已用 `modinfo` 找到 `uvcvideo.ko`。当次手动 `sudo modprobe uvcvideo` 后出现 `/dev/video0` 到 `/dev/video3`；`lsusb` 未安装不代表设备未接入。 |
| 设备权限是 `crw------- root root` | 仅临时授权 `/dev/video0` 给当前 Ubuntu 用户，未放开全部设备权限；重新接入后应重新检查。 |
| 摄像头灯亮但不出图，默认采集出现 `select() timeout` | 灯亮只表示设备在工作，不能证明收到视频帧。脱离 ROS 2 单独测试，在 V4L2 下请求 MJPG、320×240 后读到彩色帧，连续预览也成功。没有单独对照格式与分辨率的作用。 |
| Qt 提示 `/mnt/wslg/runtime-dir` 权限 `0777` 而非 `0700` | 当次窗口仍能显示实时画面，因此未修改这一目录的权限。 |
| `Ctrl+C` 和 `TERM` 当次未停掉摄像头节点 | 另开 Ubuntu 终端，通过 `ps -eo pid,args \| grep '[n]ode_object_webcam'` 区分 `ros2 run` 与实际节点，核对当前 PID 后才强制结束。不要复用历史 PID。 |
| 调整色筛后报 `SyntaxError` | 新的 `mask_red` 语句和旧 `lower_red` 粘在同一行。修复 `src` 中的代码，语法检查通过后重新编译；不要直接改 `install` 中的副本。 |
| 单色筛选仍圈到肤色 | 在保持两段 H 范围和亮度下限不变的条件下，将饱和度下限由 `90` 提到 `130`。本轮只记录定性改善，不作百分比结论。 |
