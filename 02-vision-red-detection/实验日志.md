# ROS 2 实时红色区域识别：最终记录

本次在 WSL2 中接入笔记本内置摄像头，运行古月居 `learning_node` 的摄像头节点。调参后，截图中红蓝双色包装右侧的红色区域出现绿色轮廓，左侧蓝色区域未被标记。用户反馈整体效果明显改善。

## 最终配置

| 项目 | 本次设置 |
| --- | --- |
| 摄像头 | 内置 USB 摄像头 `04f2:b758`；当次 Windows BUSID 为 `2-6`，Ubuntu 使用 `/dev/video0` |
| OpenCV 视频采集 | `cv2.VideoCapture(0, cv2.CAP_V4L2)`，MJPG，320×240 |
| 红色 HSV 第一段 | `(0, 130, 128)` 至 `(10, 255, 255)` |
| 红色 HSV 第二段 | `(170, 130, 128)` 至 `(179, 255, 255)` |
| 调参变量 | 仅将两段的最低饱和度从 `90` 提到 `130`，保留最低亮度 `128` 和两段色相范围 |

红色跨越 OpenCV HSV 色相刻度的接缝；分别用 `inRange` 筛选两段，再用 `bitwise_or` 合并。保留课程的轮廓检测和绘制逻辑。下面是两处关键代码片段，按对话中实际操作整理，不是从 Ubuntu 直接导出的完整源码。

```python
# main() 中：摄像头采集设置
cap = cv2.VideoCapture(0, cv2.CAP_V4L2)
cap.set(cv2.CAP_PROP_FOURCC, cv2.VideoWriter_fourcc(*"MJPG"))
cap.set(cv2.CAP_PROP_FRAME_WIDTH, 320)
cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 240)

# object_detect(image) 中：红色筛选
hsv_img = cv2.cvtColor(image, cv2.COLOR_BGR2HSV)
red_low = cv2.inRange(hsv_img, (0, 130, 128), (10, 255, 255))
red_high = cv2.inRange(hsv_img, (170, 130, 128), (179, 255, 255))
mask_red = cv2.bitwise_or(red_low, red_high)
```

## 下次启动

1. 保持 Ubuntu 终端打开。在 **Windows PowerShell** 执行 `usbipd list`，认准 `04f2:b758`。如果状态是 `Not shared`，先用管理员 PowerShell 执行 `usbipd bind --busid 2-6`；如果是 `Shared`，执行 `usbipd attach --wsl --busid 2-6`；如果已是 `Attached`，无需重复接入。若列表中 BUSID 变了，以本次列表为准。
2. 在 **Ubuntu** 执行 `ls -l /dev/video*`。如果接入后没生成设备，执行 `sudo modprobe uvcvideo` 后再查。如果已确认 `/dev/video0` 是本次摄像头、且权限仍是 `crw------- root root`，执行 `sudo chown "$USER" /dev/video0` 临时授权给当前账号。不用 `sudo` 启动 ROS 2 节点。
3. 在 **Ubuntu** 运行下列命令。只有改过 `src` 下的源码时，才需要在加载工作区前跑 `colcon build --packages-select learning_node`。

```bash
cd ~/guyue_ros2_ws
source /opt/ros/jazzy/setup.bash
source install/local_setup.bash
ros2 run learning_node node_object_webcam
```

正常运行不设自动结束时间。用完先在运行节点的终端按 `Ctrl+C`；再在 Windows PowerShell 执行 `usbipd detach --busid 2-6`，把摄像头还给 Windows。接入期间 Windows 不能使用这组摄像头接口。

## 验证与边界

- 采集测试返回 `读到画面: True`，帧尺寸 `(240, 320, 3)`；用户随后确认预览窗口里画面会动。
- 最终截图中红色区域被标记、蓝色区域未被标记；调参前的截图出现过肤色误圈。两张截图的姿势、目标距离与遮挡不同，不能用来量化误报下降幅度。
- 这是按颜色分割，不识别物体类别。没有统计准确率、召回率或帧率，也没有验证所有光照、距离和材质。`S ≥ 130` 是本次有效的起点，可能漏掉偏暗或不够鲜艳的红色。
