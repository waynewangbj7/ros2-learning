# ROS 2 第 9 讲：橙色识别与坐标服务

沿用已验证的 `usb_cam` 发布端，把第 8 讲的图像话题接到第 9 讲的服务端。用户确认服务端可显示橙色轮廓和实时坐标；客户端单次查询实测返回 `x: 214 y: 157`。坐标是 **320×240 图像中的像素位置**，不是距离或三维位置。

```text
终端 A：usb_cam ── /image_raw（sensor_msgs/msg/Image）──▶ 终端 B：service_object_server
终端 C：service_object_client ── /get_target_position（get: true）──▶ 终端 B
终端 C：打印 x、y 后退出 ◀── 返回最近一帧的检测坐标 ── 终端 B
```

服务接口为 `learning_interface/srv/GetObjectPosition`。相机持续发布，服务端每帧用 `CvBridge` 转为 BGR、做 HSV 筛选、找轮廓并显示；客户端每运行一次只查询一次。画面叠字由服务端逐帧更新，不需要不断调用客户端。

## 参数与验证

- 初次跑通用 HSV 范围 `[10, 120, 100]` 到 `[25, 255, 255]`；随后尝试只把亮度下限由 `100` 降为 `80`，保留色相和饱和度。没有定量对照数据，不把这次调参写成识别率提升。
- 每帧检测前将坐标清零；有通过筛选的轮廓时，使用其外接矩形的中心。若多个轮廓通过，当前代码保存循环中最后一个，并不保证选中最大或最近的目标。`(0, 0)` 是本练习约定的无目标默认值；若相机停止送帧，服务仍可能返回之前保存的坐标。
- 叠字放在 `object_detect()` 内、轮廓循环外。`if`、`imshow`、`waitKey` 同级，`putText` 在 `if` 内。保留第 8 讲识别节点与第 9 讲客户端，不改服务接口。
- [橘子轮廓截图](../../../raw/experiments/2026.11.23_ROS2橙色坐标服务_ROS2-B-261123-002/orange-fruit.png)和[橙色物块截图](../../../raw/experiments/2026.11.23_ROS2橙色坐标服务_ROS2-B-261123-002/orange-object.png)记录的是叠字前的检测效果。坐标查询有终端输出，最终画面叠字以用户确认记录。仅验证橙色区域筛选，不代表能区分橘子与其他橙色物体。

## 下次启动

1. **终端 A：相机。** 参照[已验证的 `usb_cam` 启动步骤](ROS2-B-261123-001.md#下次怎么跑usb_cam-方案)。保留 `/dev/video0`、`mjpeg2rgb`、320×240；若同一相机发布端已运行，不重复启动。
2. **终端 B：服务端。** 保持 A 运行。在 Ubuntu 执行：

```bash
cd /home/wzy/guyue_ros2_ws
source /opt/ros/jazzy/setup.bash
source install/local_setup.bash
ros2 run learning_service service_object_server
```

若刚改了 `src` 中的源码，先在工作区执行 `python3 -m py_compile src/ros2_21_tutorials/learning_service/learning_service/service_object_server.py`，通过后运行 `colcon build --packages-select learning_service`，再加载并启动。若尚未构建依赖，首次用 `colcon build --packages-up-to learning_service`。

3. **终端 C：按需查坐标。** 保持 A、B 运行。在另一个 Ubuntu 终端执行：

```bash
source /opt/ros/jazzy/setup.bash
source /home/wzy/guyue_ros2_ws/install/local_setup.bash
ros2 run learning_service service_object_client
```

窗口中先确认绿色轮廓和坐标，移动物块再查一次。画面实时显示只需 A、B。问题与处理见[排错记录](../../../排错记录.md)。
